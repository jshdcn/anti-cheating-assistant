# 领域 Playbook：移动安全

适用场景：业务涉及 Native App、设备端角色时的风险分析与方案设计。需要完整论证时按 [book-index.md](book-index.md) 回溯源文。

## 1. 基础攻防：抢底层

- 层级压制定律：浏览器级 < 虚拟机级 < 内核级 < 处理器级。谁控制更底层的基础设施，谁就能拿捏上层建筑。
- 推论：App 必须检测 root/越狱，网站不应轻信浏览器上报的数据。
- 上层一旦发现底层沦陷，最优策略是"走为上"——不与攻方在其主场缠斗。
- 攻守异势：现代防守方可大量采集情报上报服务端，以设备指纹、设备可信度等云端服务弥补客户端对抗的劣势。

## 2. 设备指纹

定义：标识设备特性的标记。两重含义：人人皆有且稳定；每台设备的每个指纹全局唯一。

可采集信息四类（按稳定性排序）：

| 类别 | 特点 | 示例 |
|---|---|---|
| 设备唯一信息 | 终生不变 | IMEI、ICCID、imsi、mac |
| 设备稳定信息 | 时序下不频繁变化 | memtotal、partition、peripheral、environ、root |
| 设备动态信息 | 合理范围内可变 | time、location、wifi、network、battery、基站 |
| 软件信息 | 刷机可变，稳定期可参考 | OS 信息、应用进程、kernel |

有效性两指标（给方案时的验收标准）：

- **唯一性**（业务上 = 漏判率/召回率）：同一设备不能获得多个指纹。破坏来源：自然变异（卸载重装/重置/维修）、人为变造（黑产改指纹）。
- **抗碰撞性**（业务上 = 错判率/准确率）：多台设备不能出现相同指纹。破坏来源：自然融合、人为伪造。

评估方法：先在无菌环境（近场观测设备群）建立自然变异/融合模型，定出合理变化阈值；再用黑盒/白盒方式评估人为变造与伪造的影响范围。

## 3. 设备可信度

- 设备指纹回答"这是哪台设备"，设备可信度回答"这台设备值不值得信"。
- 可信度服务用于屏蔽非真实设备复制/模拟产生的虚假指纹，是指纹服务的前置闸门。

## 4. 多源复合定位

- 单一定位源易被单点伪造（如 GPS 模拟器）。应融合 GPS、基站、WiFi、IP、传感器等多源信号交叉校验。
- 定位异常判定看一致性而非单点精度：各源互相矛盾即为风险信号。
