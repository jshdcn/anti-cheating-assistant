# 领域 Playbook：资金安全

适用场景：涉及账期、信贷、支付结算、发票业务的风险分析。资金安全 = 业务/账务/财务三层中财务层全部 + 其与账务层的对账。需要完整论证时按 [book-index.md](book-index.md) 回溯源文。

三分结构：**财产安全**（用户个人的钱）、**信贷安全**（平台的钱）、**支付安全**（监管法定义务）。

## 1. 财产安全

账号安全在财产域的延伸，但有一个微妙差异：账号安全关注"操作人是不是账号持有者"，财产安全还要证明"**操作人是不是财产的合法持有者**"（账号持有者未必是财产所有者）。

拒付案例的启示：

- 卡组织模式（Visa/MasterCard）：压印+签名 → 成熟拒付处理机制，商户须按卡组织要求做所有权验证；
- 中国互联网模式（银联/微信/支付宝）：手续费低养不起争议处理机器 → 几乎 100% 交易要求密码或更高验证，从根源规避拒付；
- 本质是**交易成功率与拒付率的平衡**。少量拒付（不触发罚款线）可接受，前提是对绑卡和支付环节有完整监控（如 MasterCard Ethoca），能及时拦截或退款。

## 2. 信贷安全— 坏账全流程

**坏账四分类**（按计价方 × 支付方式）：平台计价线上、平台计价现金、非平台计价线上、非平台计价现金。

五步处置流程：

| 步 | 做什么 | 要点 |
|---|---|---|
| 定损 | 坏账归一化 | 非平台计价费用由客服确认（第三方费用要凭据比对、议价费用要协商证据）；现金坏账通过**债务解耦**转移成线上支付（买卖双债权债务主体都改为平台，税务关系一并转移） |
| 定责 | 确认实际支付状态 | 线上看支付流水；现金要受事方出核验过的线下凭证；两种支付并存时需多次握手 |
| 催收 | 向买方追款 | App 弹窗/Push/短信/自动外呼/人工外呼；可要求同设备或同支付账号用户发单前代付待支付账单 |
| 垫付 | 向卖方补款 | 资损直接来源，慎之又慎。五前提：买方未支付、订单非刷单、买卖双方不认识、非恶意套取（规则过滤频繁大额）、卖方费用可信度高（看收费历史） |
| 降发生 | 避免坏账发生 | **重中之重，坏账率是北极星指标**。核心手段是担保：授信前风控模型对当单支付意愿评分，按风险等级由高至低给担保——充值担保（1 至多倍，黑产见充值即跑，可找代充）、免密代扣（含信用卡预授权）、禁现金改线上预付、提醒卖方验货收款再卸货、分单干预（派给有反诈意识的卖方）。以上皆不可为则拒绝授信 |

另：**宣传教育**——联合警方向卖方推反诈宣传；业务支持卖方扣货反制的应允许甚至鼓励（再好的风控也不应取代卖方先天自卫能力）。

## 3. 支付安全— 法定义务

| 义务 | 要点 |
|---|---|
| 反洗钱 | 核心是 KYC，分账号层（复用账号安全验证能力）和交易层（全面收集交易信息并验真；可疑交易是阻断资金流转要求补证据的优质理由）。不直接碰钱的业务配合金融机构即可，避免自行加戏 |
| 反套现 | 平台计价金额不易被套现（有真实履约监管），**非平台计价金额是重灾区**。特征：大额或小额高频、买卖双方串通。发现后增加交易摩擦 |
| 反恐怖融资 | 基础仍是 KYC，但**涉案即有罪、不看金额**。除增强准入外，须有及时更新的黑名单，尽早发现尽早阻断 |
| 反二清 | 无证机构留存商户结算资金自行清分 = 二清。平台模式须让所有商户在支付渠道开户（进件），避免被动触发 |
| 反虚开发票 | 入刑罪名。风险三处：刷单（平台计价费用）、刷票（非平台计价费用）、发票黄牛（发票抬头） |
